# Wedding Model Video Editing

## When to Use

在用户要求婚纱模特视频剪辑、DaVinci Resolve 调色、逐片节点、Magic Mask 2 皮肤跟踪、Face Refinement、人物比例统一、音乐卡点、背景局部修正、静帧验收或高清渲染时使用。

也在用户说“继续”“只修第 X 秒”“分辨率再提一档”“保持一致性”“渲染我看看”时加载，以便恢复并约束已有婚纱项目。

## Procedure

### 1. 先确认真实能力与当前状态

1. 检查 Hermes 当前可用的 MCP、GUI/Computer Use、终端和 DaVinci Resolve 状态。
2. 优先使用可回读的 Resolve MCP 或 Scripting API；工具名称以实际列表为准，不虚构命令。
3. MCP 未覆盖的面板操作才使用 GUI。GUI 验收使用随机静帧，不通过连续播放判断。
4. 只有终端、没有 Resolve 控制能力时，只做素材分析、转码、抽帧和交付检查；明确说明不能直接修改工程，禁止假装已经调色。
5. 用户说“继续”时，先回读当前项目、时间线、轨道、渲染队列和输出文件，再从最后一个已验证状态继续。

### 2. 把自然语言整理成作业规格

提取并记录：素材路径、参考片、音乐、用途、时长、画幅、分辨率、帧率、节奏、人物肤色方向、必须处理的时间点、禁止事项、输出目录和命名。

只在缺失信息会明显改变成片时提问。否则采用以下默认值：

- 单人婚纱正式交付：7 节点预设。
- 肤色：白皙、干净、通透，同时保留少量自然血色。
- 验收：随机静帧、切点前后、指定问题时间点前后约 0.5 秒、最后一帧。
- 输出：MOV/H.265；普通竖屏 1080×1920；“再提一档”使用 2160×3840 竖屏 4K；保留原帧率。
- 版本：新工程、新时间线或新文件名，不覆盖已验证版本。

### 3. 保护原始内容

1. 保存项目并创建明确命名的时间线版本或项目副本。
2. 保留原始素材、原工程、已验证成片和 DRP。
3. 破坏性操作前先归档；用户说“停”时停止可停止的跟踪或渲染，不继续提交新任务。
4. 工作树或项目状态不确定时先读取，不先删除、覆盖或重置。

### 4. 完成剪辑与构图

1. 先读取 `references/davinci-resolve-workflow.md`。
2. 先剪辑和构图，再调色。保持相邻镜头的人物高度、脸部大小和动作连续性。
3. 半身和头面部约占 65–75%；全身约占 25–35%，用于展示裙摆、姿态和场景。
4. 保留头顶、下颌、肩线、手势和裙摆；不靠露黑边的缩小解决近景问题。
5. 使用音乐强拍切镜时先检测重拍并量化到时间线帧格。

### 5. 选择 3／5／7／9 节点预设

建立节点前读取 `references/node-presets.md`，选择最小够用档位：

- `3`：快速基础。干净素材、试剪、预览版。
- `5`：标准人像。单人、稳定光线、简单背景。
- `7`：婚纱精修默认。独立 NR、WB/EXP、CONTRAST、DENSITY、SKIN、FACE、LOOK/FINISH。
- `9`：复杂商业级。多人独立肤色、复杂背景/天空、局部与输出管理。
- `9+`：同画面超过两人。每个人增加独立皮肤节点或并行分支，不共用遮罩。

每个有效素材片段建立独立节点实例。只统一节点顺序和最终观感，不链接一级曝光、肤色、Face Refinement 或局部参数。

### 6. 按固定顺序调色

1. 先完成一级白平衡、曝光、对比度和色彩密度。
2. 保护婚纱蕾丝和白纱高光，不追求过亮。
3. 再处理皮肤、Face Refinement 和背景局部。
4. 最后制作 Look、轻微锐化/暗角与输出微调。
5. 色彩管理工程不重复添加 CST；不要用 Look 掩盖曝光或遮罩问题。

### 7. 使用 Magic Mask 2

1. 单一连续人物默认只在脸部皮肤设置一个正跟踪点。
2. 使用双向跟踪；逐片顺序处理，不并行启动多个长跟踪任务。
3. 同一时间线片段存在人物位置突变的多个不连续镜头时，每个镜头段各设一个点。
4. 同一画面多人时，每个人使用独立皮肤节点、独立点和独立参数。
5. 复制调色后必须重新跟踪目标片段，不把参考镜头缓存当作有效结果。
6. 单点确实漏选时才增加最少量样本；点数过多会增加算力负担并可能使跟踪停在 0%。

### 8. 使用 Face Refinement

1. 放在基础肤色修正之后。
2. 只做轻度肤质、眼神和面部光线整理。
3. 避免改变五官、强磨皮、塑料感和重复锐化。
4. 以跨镜头一致为优先，不让某个近景单独“更好看”而破坏整体。

### 9. 区分多人肤色但不推断身份

1. 不根据外貌自动判断人种、族裔或审美偏好。
2. 使用客户明确说明的市场和风格方向。
3. 客户指定小麦色时采用克制暖金/古铜方向，避免橘红和脏黄。
4. 多人镜头先统一场景曝光和白平衡，再逐人修正肤色，保留自然差异。

### 10. 静帧验收

1. 不把时间线连续播放作为主要判断依据。
2. 随机抽取全身、半身和近景；在每个切点前后抽固定偏移帧。
3. 用户指出第 X 秒时，至少检查目标点前后各约 0.5 秒。
4. 检查脸、颈肩、手臂一致性，遮罩连续性，婚纱纹理，背景误选，人物比例和最后一帧。
5. 只修问题片段，不改已经验证的共享参考或无关镜头。

### 11. 渲染与恢复

1. 渲染前保存项目，使用独立文件名和用户指定目录。
2. 建立任务后回读状态；“加入队列”不等于完成。
3. Resolve 报“无法加载项目”时：保存并导出 DRP，导入明确命名的独立渲染副本，载入正确时间线，清空失败队列，再建立任务。
4. “分辨率再提一档”默认保留剪辑、调色、音乐、帧率与时长，只把竖屏输出改为 2160×3840，并在文件名加入 `_4K`。
5. 使用终端读取最终文件参数，并抽取指定时间点与片尾静帧。

### 12. 交付

只有在以下条件全部满足后才说“完成”：

- Resolve 任务状态为完成，或输出文件已稳定写完且可读。
- 视频时长、帧数、分辨率、帧率、编码正确。
- AAC 48 kHz 立体声音轨存在。
- 指定问题时间点、随机静帧和最后一帧通过。
- 原版本未被覆盖。

最后提供新成片的绝对路径，并简述规格、节点档位、肤色方向和验收结果。

## Pitfalls

- 不要在没有真实工具回读时声称已经修改、跟踪或渲染。
- 不要为一个连续人物密集打点；默认一个脸部皮肤点。
- 不要复制 Magic Mask 缓存后跳过重新跟踪。
- 不要让多人共用一个皮肤遮罩或肤色参数。
- 不要凭人种刻板印象自动套肤色风格。
- 不要用连续播放代替静帧验收。
- 不要覆盖原工程、已验证成片或旧分辨率版本。
- 不要把渲染任务创建成功当作文件交付成功。
- 不要在 Resolve 正忙时重复提交跟踪或渲染调用。

## Verification

逐项确认：

1. 项目、时间线和输出版本名称正确。
2. 每个有效片段使用选定的 3／5／7／9 节点档位，参数独立。
3. Magic Mask 点数合理，双向跟踪完成；多人分别处理。
4. 随机静帧中的肤色、婚纱白场、背景中性和人物比例一致。
5. 指定问题时间点及其相邻帧通过。
6. 最后一帧有效，无黑尾或断音。
7. 最终文件可打开；分辨率、帧率、视频编码、音轨和时长符合规格。
8. 向用户提供真实存在的本地文件路径，不提供不存在的成果。

需要卡点动效时读取 `references/cardpoint-dongxiao.md`；需要 TikTok 魔幻风格时读取 `references/tiktok-fantasy-look.md`；最终交付参数参考 `references/finish-presets.md`。
